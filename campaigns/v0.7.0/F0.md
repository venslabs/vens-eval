## 4. Execution

- **Machine:** the maintainer's own Mac (Mac16,6, Apple M4 Max, 36 GiB, macOS 26.7.3 build 25G342, arm64), the
  runner on Python 3.12.12, sleep disabled (`pmset`), recorded in each campaign folder's `machine.json`. No paid run on
  CI. Cause: spec §2 A9 fixes the machine; one machine keeps the time line comparable.
- **Concurrency 1:** one runner per folder (a lock), one vens at a time; before each paid run the runner refuses to
  start while another `vens*` process runs. Cause: A9's time shares neither the machine nor the accounts.
- **Command:** `vens generate --llm openai|anthropic --config-file CONFIG --sbom-serial-number urn:uuid:0…01
  --debug-dir debug --attest REPORT vex.cdx.json` (`--attest` on both arms, maintainer 27/11), environment limited to
  `PATH`, `HOME`, `TZ=UTC`, the proxy's base URLs, the key and the model.
- **Cache regime** (spec §2 "The cache"): each run starts with empty local caches; no prewarming, no cache busting, no
  cooling wait. OpenAI's automatic prefix cache is shared by both arms in the one organisation, interleaved; vens sends
  no `cache_control`, so an Anthropic cache token breaks the profile and leaves that A9 cost line UNDETERMINED (reader).
  The cost line is reread with cached tokens priced as input; a state that differs reads UNDETERMINED. The time line
  prints each arm's cached share. Cause: the initial state is the same for both versions, and nothing is warmed on
  purpose.
- **Order:** repetition outermost. Units (a block, or a DIR pair with its members a, b and c) crossed with the models
  are ranked by `sha256("vens-kpi/1.0/v0.7.0/order" ‖ seed ‖ repetition ‖ unit ‖ model)`, each part NUL-terminated,
  lowest first. The two arms run back to back on the same unit; the arm that leads alternates from one position to the
  next; a unit's members run back to back within each arm. Cause: stages hold whole repetitions; pairs compare runs
  close in time; each arm leads half the units.
- **Seeds**, each `sha256(domain NUL spec-1.0 sha256 hex)`:
  - order: domain `vens-kpi/1.0/v0.7.0/order-seed` → `74920acb17aa8cee8d95d38944112aedbbe07e6d61fa28aa60ab4a033a6eb5fe`;
  - bootstrap: `vens-kpi/1.0/v0.7.0/bootstrap-seed` → `287523f1b40fe3f4a0b41c28e9df49c69a408aee0e134c8196ddf4c9fd568b00`;
  - calibration: `vens-kpi/1.0/v0.7.0/calibration-seed` → `93aa1f0b238474c6d66f4599a734a91ea17c70933503c7944ff5c99131a02607`.

  Cause: public and recomputable, fixed before any data or output, chosen by no one.
- **Repetitions:** 0 (the smoke), 1-2, 3, 4-5, then 6-8 for the extension.
- **Timeout:** 3600 s per run; past it the runner kills vens and the run is aborted (an A7 result, its cost kept, its
  time left out). Cause: a hang guard, several times a 100-CVE run's expected length (about 80 serial calls). For the
  completion gate such a run is an A7 result, not a gate failure, unless the canary fails right after it: then it is a
  device failure and takes the network path below. The request it leaves in flight is counted at its maximum in the
  ledger, and the usage gate lists it without failing on it.
- **Network canary:** before each paid run, a TCP and TLS handshake to `api.openai.com:443` and
  `api.anthropic.com:443`, no request. While it fails, the runner retries it every 30 s for up to 2 h, then halts as a
  device failure; a STOP still stops it. A failed run's single re-attempt starts only after the canary passes. Cause:
  a short network cut on the maintainer's Mac must not end the campaign, and nothing read changes: the waits fall
  between runs, and a re-attempt replaces its failed attempt.
- **Records per run:** `attempt.json` (written before vens starts), `vex.cdx.json`, `vex.attestation.cdx.json`,
  `debug/`, `vens.stderr` with every form of the key cut out, `a9.jsonl`, `a9.json`.

- **Runs per repetition:** 238 blocks (3 sealed, 3 sentinel, 12 INV, 220 DIR) × 2 models × 2 arms = 952.
- **Ceilings** (`estimates_usd`, USD per run, both arms): #310 Panel A's candidate cost at batch 1, $1.65
  (`claude-sonnet-4-6`) and $0.41 (`gpt-5.4-mini`) per 74-CVE context scan, so $0.022298 and $0.005541 per CVE, times
  each kind's N: sealed 100 → $2.2298 / $0.5541; INV 30 → $0.669 / $0.1663; sentinel 4 → $0.0892 / $0.0222; DIR 1 →
  $0.0223 / $0.0056; smoke 45 → $1.0035 / $0.2494. R gets the candidate's ceiling. Cause: batch 1 bounds batch 10
  (the system prompt is shared by fewer CVEs); R's real ratio is known only after the smoke, and a ceiling must not
  rest on it.
- **Expected spend:** about $110 to $160 for stages 0 to 3. Basis: the mock price preflight at $0 (prompt bytes per
  run, both binaries): R sends about 0.2 of the candidate's bytes on the 100- and 30-CVE reports and 0.35 on DIR's
  one-CVE reports, about 0.23 overall; the candidate's quickstart run on C1 sends about 0.7 of its ceiling's worth.
- **Cap:** $300, hard-coded in the runner; a campaign file cannot raise it.
- **Spend guard:** every request reserves `(request bytes + 4096) × the dearest input-like price + max output ×
  output price`, `reserve_factor` 1.0; max output is the body's `max_tokens` (16384, Anthropic) or 128,000 (OpenAI,
  about $0.58 per request in flight). A request that would pass the cap or the stage budget is refused (HTTP 402, not
  forwarded) and halts the campaign. Settled at the grid price, at its maximum when sent and unpriceable, at 0 when
  never sent or answered with an error; a reservation left open is settled at its maximum. A run whose estimate does
  not fit is not dispatched. Cause: request bytes bound the input tokens; the overhead covers what the provider adds.
- **Cut order** (spec §6 "the spending"): INV stays at 30 bases and the controls at 20 throughout this campaign; no
  reduced profile exists. The extension is dropped first (§10); a stage 0 to 3 whose runs still to do do not fit, at
  their ceilings, under the cap and the stage budget does not start, and the campaign stops (the runner checks it at
  the stage's start). Never cut: the repetitions, the sealed 100 × 3, a model, R's runs, the DIR pairs and controls,
  the INV bases. Cause: a reduced profile would need selection and execution rules this file does not freeze.

## 6. Control: go, stop, gates, verdict at the stage reached

- **Go:** a stage starts only on its `GO-stage-k` file, which the coordinator writes after asking the maintainer. At
  each stage's start and end, one line to the maintainer: what was spent, what comes next. Cause: the maintainer's
  26/11 rules (stages, the go at each one). Stage 0's go is given (27/11) and takes effect once F0 is signed and
  approved.
- **Stop:** the word "stop" to the coordinator, or a `STOP` file in the campaign folder, both checked before every run;
  the run in progress finishes; a resume reruns nothing. Cause: the maintainer's 26/11 rule.
- **No idle time:** the next stage starts at the maintainer's go; nothing else waits. The calibration (§9) runs at the
  end of stage 3, at $0, between paid runs.
- **Technical gates**, after repetition 1 and at each stage's end, reading no verdict line and spending no alpha:

  | Check | Fails the gate when |
  |---|---|
  | completion | a scheduled run neither completed nor ended as an A7 result (a non-zero exit, or a run killed at its timeout with the canary passing right after) |
  | usage | a forwarded request is not priced (`usd_not_measured`), the one a timeout kill left in flight excepted |
  | spend | a run passes max(1.5 × its ceiling, $0.05) |
  | device | a device failure is left standing (`device_failures_max` 0; one resolved by its single re-attempt, which waits for the canary, is listed) |
  | mechanical | the reader's `check` (A1, A2, A8) did not run, reported a setup problem, or reported a reader hash other than the config's frozen `reader_sha256`; a stub on a paid run |

  A setup or device problem fails the gate and **halts spending**; the coordinator takes it to the maintainer. Cause:
  a problem shows at the cost of one repetition, never after the whole budget (the maintainer's 26/11 rule). A
  network cut shorter than the canary's 2 h is waited out between runs and fails no gate (§4).
- **A violation in vens's outputs is a result, not a gate failure:** the A1, A2 or A8 violations the check finds are
  recorded, the line reads FAILED from then on, the runner prints it and the maintainer is told at once; the gate
  passes on it, and the maintainer decides stop or go as at any stage.
- **Verdict at the stage reached:** the last stage whose scheduled runs all finished, whatever its end gate gave; at
  stage 1 at least: no verdict before stage 1's runs have finished. Every deterministic 100% violation observed stays
  blocking, those from an unfinished later stage included (the reader checks every run present). Any AUTHORITY label
  observed in a produced output, including an unfinished later stage, remains a non-waivable failure in the verdict at
  the last completed stage. Labelled "verdict at
  stage k of 3 (V2 incomplete)", "at stage 3 (V2 complete)" or "at stage 4 (extension)"; earlier stages' states stay
  printed; a PROGRESS ESTABLISHED before stage 3 prints "size possibly overestimated (early stop)". A campaign that
  ends before stage 1's runs finish has no verdict; its runs and every violation seen are published, and the sealed
  set counts as read for this candidate. A stopped campaign is not complete; its runs are kept and published.

## 8. Lines and tests

- **Primary lines:** 71, from `python -m vread lines` on F0's structure (§14): A5 repetitions 6, guard 6, models 3;
  A9 cost 6, time 6; A6 noise 18, shift 12, pattern 12; A4 (V4) 2. The size stays 71 at every stage; an unavailable
  test stays with p = 1.
- **A5 and A6 noise:** d per CVE, cluster bootstrap over CVEs, **200,000 draws**, seed per line from the bootstrap
  seed and the line id, percentile interval two-sided at 1 − α_k (`inverted_cdf`); p = (1 + #{d* beyond the
  threshold}) / (1 + B), doubled; a line's p is the smaller of its failure and gain p. Corrected bound: the percentile
  bound at 1 − α_k / (m − rank + 1). Cause: 20,000 draws give p ≥ 1.0 × 10⁻⁴, above Holm's first threshold at stages 1
  and 2 (0.005 / 71 = 7.0 × 10⁻⁵), so no line could be decided there; 200,000 give 1.0 × 10⁻⁵.
- **A5 two-band** (repetitions and models lines): d₂ per CVE = the share of the line's comparison pairs (repetition
  pairs; cross-model pairs) two bands or more apart, candidate − R, same cluster bootstrap; its failure p joins the
  line's (§11 #1).
- **States:** a failure confirmed at the line's Holm level reads FAILED, whatever the gain's p; a confirmed gain reads
  PROGRESS ESTABLISHED only on a line that holds, otherwise UNDETERMINED.
- **A9:** ratio of means over paired run blocks, Fieller-t, df = pairs − 1, normal blocks assumed; an unbounded
  interval is UNDETERMINED.
- **A6 test (1):** the mean signed shift per CVE in the instructed direction, bootstrap over CVEs, **one-sided** in
  that direction: p = (1 + #{s* ≤ 0}) / (1 + B), one line per direction. Cause: each direction is its own test (spec
  §3 "once per direction"), and the one-sided test fires more readily, so it cannot help the candidate; its false
  alarms are calibrated.
- **A6 test (2):** the number of CVEs whose every planted repetition is strictly beyond the base's range, against the
  exact per-CVE permutation null, Poisson-binomial over CVEs.
- **A6 rubric (3):** §7.3, no alpha, blocks from the first output.
- **Tests required at each stage** (A6's assembly): stages 1 and 2: noise, test (1), the rubric on every planted
  output; stages 3 and 4: also test (2) (5 repetitions, then 8).
- **V4:** exact Clopper-Pearson, one-sided at α_k/2. Printed targets: Clopper-Pearson or bootstrap at 95%,
  uncorrected, never blocking.
- **A7's justified fallbacks** (usable coverage): `missing-cvss-v3` and `no_description` on M, O and EE. Cause: both
  are fixed by the scan before any run and identical for both arms (no usable v3 vector, no description), and the 26/11
  decision keeps the 9s. A `cannot_tell` or an off-list answer is the model's own and is not justified.
- **A8:** the attestation is required (`--attest` on both arms); without it the claims are not checked and A8's trace
  reads UNDETERMINED.
- **Not measured:** A3 (V5 deferred) and A8's comprehension tasks.
- **Rereads:** δ × 0.5 and × 2 on A5's δ, A6's noise margin and A9's 5% tolerated loss (1.025 and 1.10), printed
  beside the verdict; the two-band margin stays zero.

## 9. Calibration (spec §3 "Multiplicity")

| Item | Value | Cause |
|---|---|---|
| Generator | `r_run_resample`: per unit and model, each arm's repetition i is a whole R run of that unit drawn uniformly with replacement; for INV, the candidate's base and variants are drawn from R's base runs | the spec's same-version replay on R's campaign runs |
| Assumptions | R's runs of a unit are exchangeable; a whole run is the unit (its batches, cost and time kept); under the null the variants behave as the base; every look is taken and the extension granted to every line UNDETERMINED at stage 3 (the same selection as §10); R's run count printed | the conservative case for the looks |
| Procedure | each simulation reproduces two full-sized arms through stages 1 to 4, Holm and the stage-1 models margin included | spec §3 |
| Simulations | 1,000, each with its own stream (`calibration/sim<k>`), run in parts (`calibrate --part K/N`, then `calmerge`) | a part per core; about 35 min on 12 cores at $0 |
| Draws per simulation | 200,000 | the same as the reading, or stage-1 and stage-2 alarms could not occur in the simulation |
| Estimator | one-sided 90% Clopper-Pearson upper bound of the false-alarm rate, ≤ 0.05 per line | simulation noise cannot pass a line that alarms too often |
| When | **once**, at the end of stage 3 and before the extension decision, or at the last stage reached if the campaign stops earlier, on R's runs up to that stage (`calibrate --stage k` draws only repetitions 1 to stage k's last); never rerun after stage 4, whose looks the simulations already cover. The reports of stages 1 and 2 are uncalibrated and say so | no paid run is in flight between stages, so A9's time is untouched |

A line not calibrated is UNDETERMINED, "false alarms not checked"; a deterministic 100% rule still applies.

**Known limit, for the reviewers:** with few R runs (2 at stage 1), both simulated arms often draw the same runs,
which can understate false alarms; the upper-bound estimator and the printed R-run count are this campaign's answer.

## 10. Extension trigger

One extension of 3 repetitions (6 to 8), only if (a) a primary line reads UNDETERMINED in the **calibrated** stage-3
reading, (b) the full cost of the selected blocks fits: their 3 repetitions for both arms and both models plus any
catch-up, at the mean observed cost per block, model and arm of stages 1 to 3, under what is left of the cap
(`gates/stage-4-budget.json`); if it does not fit, there is no extension; and (c) the maintainer's go. The selection,
written by `python -m vread extension … --calibration` into `extension.json`: the union, over the lines UNDETERMINED
at stage 3, of an A5 or A9 line's sealed block, an A6 cell's base and variant, and, when either A4 field reads
UNDETERMINED for a model, the a and b members of the pairs still undecided for it. Never for a figure seen before stage
3. At stage 4 only the lines UNDETERMINED at stage 3 are re-read, the others keep their stage-3 state with p = 1;
undecided pairs are recounted by 5 of 8; an undecided control is not. At stage 4, an A6 cell whose base and variant
are not both extended retains its stage-3 statistical reading and rubric coverage. Unscheduled repetitions are not
missing outputs. Tests (1) and (2) are re-read only where both base and variant are extended. Any AUTHORITY label
observed in a produced output, including an unfinished later stage, remains a non-waivable failure in the verdict at
the last completed stage.
